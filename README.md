# Corvis Trading — wallet/backend foundation

This package contains a Node.js/Express backend and responsive dashboard. It adds persistent bot profiles, a generated Solana keypair for each bot, AES-256-GCM encryption for bot private keys at rest, treasury address/balance lookup, per-bot SOL balance lookup, and confirmed SOL withdrawals from a configured treasury to a Phantom/public Solana address.

## Important status

**This is not a production-ready trading bot and automated live trading/sniping remains disabled.** It does not discover token launches, screen tokens, obtain Jupiter swap transactions, submit swaps for bot strategies, calculate token mark-to-market value, or run take-profit/stop-loss automation. Stats only reflect recorded app trade records; none are generated by a live strategy in this build. The interface intentionally labels live trading as locked.

Bot deletion does not transfer funds automatically. An optional SOL-only sweep path exists but is disabled by default; it does not sweep SPL tokens. Do not enable it on mainnet without testing, review, and explicit operational controls.

## Deploy

1. Use Node.js 20 or newer.
2. Upload the ZIP contents to the repository/deployment root. Do not upload `node_modules`.
3. Run `npm install`, then deploy with `npm start`.
4. Configure environment variables in Render (Environment), not in GitHub:
   - `ADMIN_API_TOKEN`: long random secret used to authorize bot creation, changes, deletion and withdrawals.
   - `WALLET_ENCRYPTION_KEY`: exactly 64 hexadecimal characters (32 random bytes). Generate with `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`.
   - `TREASURY_SECRET_KEY`: treasury Solana secret key as base58 or a JSON array of 64 bytes. **Never commit this value or share it in chat.**
   - `SOLANA_RPC_URL`: trusted Solana RPC endpoint. Use devnet while testing.
   - `SOLANA_NETWORK=devnet` for devnet; set `mainnet-beta` only when intentionally using mainnet.
   - `DATA_DIR`: writable persistent disk path, e.g. `/var/data` if a Render persistent disk is mounted. Without persistent storage, wallet/profile records may be lost on redeploy/restart.
   - Leave `ENABLE_LIVE_SWEEP=false` unless you have reviewed and tested the sweep behavior on devnet.
5. If you need a persistent database, add PostgreSQL and migrate the JSON store before production. The local JSON database is intended as a starter, not a multi-instance database.
6. Never fund the treasury until you've tested on devnet, checked RPC/network settings, secured the environment, and verified backup/recovery procedures.

## Wallet model

- The treasury wallet is loaded from `TREASURY_SECRET_KEY`; the server returns its public address and queried SOL balance, never its private key.
- Each bot gets its own generated Solana keypair. The secret key is encrypted using `WALLET_ENCRYPTION_KEY` before persistence. Keep both treasury and encryption key in hosting secrets; losing the encryption key makes stored bot wallets unrecoverable.
- The browser uses the `ADMIN_API_TOKEN` to authorize administrative actions. Use this only in a trusted private dashboard; production should add real user authentication, CSRF protection, rate limiting, audit trails, and access controls.
- Withdrawals send native SOL only. SPL token withdrawals and token balances are not implemented.

## API overview

- `GET /api/status`, `GET /api/bots`, `GET /api/events`
- `POST /api/bots` (Bearer admin token) creates a bot + dedicated wallet
- `GET /api/bots/:id/stats` gets bot wallet SOL balance and recorded stats
- `PATCH /api/bots/:id` (Bearer admin token) starts/pauses paper monitoring only
- `DELETE /api/bots/:id` (Bearer admin token, `{ "confirm": true }`) deletes a paused profile; wallet assets remain where they are
- `GET /api/wallet` gets treasury public address and SOL balance
- `POST /api/wallet/withdraw` (Bearer admin token, destination, amount, and explicit confirmation) sends native SOL from treasury

## Before enabling real trading

Implement and audit: token-launch/indexer feed, token safety checks, Jupiter quote/swap integration, bot-wallet transaction signing, transaction simulation, slippage and priority-fee bounds, maximum daily loss and exposure limits, RPC failover, durable trade ledger, idempotency, user authentication, rate limiting, and monitoring. Test the full system on devnet with no mainnet funds first. Automated live trading is intentionally not enabled in this build.

## Render dependency installation fix

This project imports `@solana/web3.js` from `server.js`, and it is declared in `package.json` under `dependencies`. Deploy from the directory containing both `server.js` and `package.json` (normally the repository root). The included `render.yaml` explicitly runs `npm install --no-audit --no-fund` before `npm start`.

If Render still reports `ERR_MODULE_NOT_FOUND`:
1. In Render, open the service's **Settings** and confirm **Root Directory** is blank (or points to the folder containing `package.json` and `server.js`).
2. Set **Build Command** to `npm install --no-audit --no-fund`.
3. Set **Start Command** to `npm start`.
4. Trigger **Manual Deploy → Clear build cache & deploy** so Render reinstalls dependencies from the latest commit.
5. Check the build logs for `@solana/web3.js` being installed before the start command runs.

Do not set the build command to only `node server.js`; that starts Node without installing dependencies.
